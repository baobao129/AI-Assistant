## 关键决策（详见 `DECISIONS.md` ADR-037）

1. **PDF 库 pypdf 6.19.0**（BSD-3、纯 Python）；API 以**已安装包**核验，不凭记忆。
2. **双限分片**：先按 `MINERU_MAX_PAGES` 贪心，再对超 `MINERU_MAX_BYTES` 的片二分（显式栈，深度 ≤ log2(页数)）；单页超限 → `shard_too_large`。313 页 → `1-200` / `201-313`。
3. **复用键** `(分片字节 sha256, parser_provider, parser_options)`；命中复制文本、`reused=1`、不调用 provider。
4. **超时语义**：`submit` 是副作用步，batch id 立刻落库；`fetch` 超时 → `parse_timeout`（≠ `parser_unavailable` / `parse_failed`）；重试**续轮询**而非重新提交。
5. **`reused` 是 success 的标志位**，不是第五个状态 —— 这样「闭合 = 全部 success」保持单一判据。
6. **页码诚实**：manifest 的 1-based 页范围是权威来源；无可靠页码记 `NULL` / `pages=0`，绝不伪造第 1 页。chunk 级页跨度属 P3。

## 踩到的坑（下次直接用）

1. **宿主 httpx 默认走代理**：本机环境有 `HTTP_PROXY=http://127.0.0.1:11596`，`httpx.Client()` 默认 `trust_env=True`，访问 `127.0.0.1:8000` 会返回 404（登录 POST 却能过，极具迷惑性）。连本机容器一律 `httpx.Client(trust_env=False)`。curl 不受影响。
2. **不要 `grep .env`**：脱敏正则没命中 `MINERU_API_KEY=`（KEY 在 `=` 之前），把 token 打进了终端。要看档位就用 `Settings()` 读，或只 grep 键名。
3. **`slice_pages` 不复制文档 Info**：`PdfWriter.add_page` 只复制页对象，所以「给 PDF 加 metadata 让字节唯一」对**分片**无效 —— 不同测试的空白页会切出完全相同的分片字节，从而命中复用键。要让分片字节唯一，必须改**页面对象**（例如 `add_blank_page` 的宽高）。
4. **`document_chunks.chunk_id` 的坑已修**（VARCHAR(64)）；本轮无回归。
5. **P0 遗留的 313 页文档**处于 `available` + `active_index_version=NULL`（G19），重复上传被指纹去重并**报告 success**（G20），reindex 又因 `content_unavailable` 报 409 —— 必须先显式删除才能做干净的真实摄取。这是 G19/G20 的具体证据。

## 关键决策（详见 `DECISIONS.md` ADR-038）

1. **结构来自 provider 块输出**（`content_list.json`），不从合并文本猜；缺失/超预算只回退并记录。
2. **页码绝对化**：`绝对页 = shard.page_start + block.page_idx`；无来源记 NULL，**绝不伪造第 1 页**。
3. **token ≠ 字符**：中文 1 token/字符、英文 1/3 token/字符；同一预算下两种语言的字符数不同。
4. **文档文本与索引同源**：有块时 `document_contents` 由块派生，否则「存起来的文本」与「被索引的内容」会是两份不同表示。
5. **父块展开在 Graph 内经注入的窄协议**，Graph 不碰仓储类型/数据库；去重按 parent chunk ID。
6. **命中证据必留**：放不下时截断该段，而不是整段丢弃；父块背景放不下直接跳过。

## 关键设计（详见 ADR-039）

1. **三个标识严格区分**：`authorized_document_ids`（服务端即时算，绝不入 State）、`requested_document_ids`（未证明）、`document_scope`（校验后入 Graph）。
2. **A′**：有作用域时 knowledge/structured/mixed 都收敛到 `knowledge`；两者都不命中仍是 `general`（寒暄不受影响）；无作用域逐行不变。
3. **两处校验**：建 Run 快速失败（409，无任何副作用）+ 检索边界权威复检（零 provider 调用）。**不同边界负责不同情形**：他人/删除/未知 ID → 建 Run 时；建完后失去 active 版本 → 检索时。
4. **不落 Run 行**：确认只有审批 successor 会被重派发（`list_pending_successor_run_ids`），普通 Run 从不重放 → 内存传递 + Checkpoint 继承足够。
5. **`request_initialize` 绝不重置 `document_scope`** —— 否则 HITL 续跑会静默把范围放回「全部授权文档」，属阻断级缺陷。

## 实测证据

- e2e smoke **2 passed**（真实容器；需 `SMOKE_BASE_URL` + `SMOKE_USERNAME/PASSWORD`，且必须 `NO_PROXY=127.0.0.1`）。
- 在线验收（真实容器 + 真实 PDF + 真实 bge-m3 + 真实 LLM）**ALL CHECKS PASSED**：
  - 问「金额上限和数量限制」+ 选中文档 → `intent=knowledge`，**不再被 SQL 抢走**；引用 5 条且只来自选中文档。
  - 「你好」+ 作用域 → `intent=general`。
  - 伪造 ID → 409 `document_scope_unavailable`，文案不泄漏。
  - 选中「available 但无 active 版本」的文档 → 终态明确提示 `no longer available`（而不是「文档里没有」）。
  - SSE 重连 → 只有一条 final，引用仍在作用域内。

## 踩到的坑

1. **`app.state.container` 只在 lifespan 里装配**：`TestClient(app)` 必须当上下文管理器用（`with TestClient(app) as client:`），否则 `get_container` 抛 401 "application is not ready"。清理也要放在 `with` 内部，因为退出时 lifespan 会 `container.close()`。

4. **ruff 会重排代码**：用脚本做字符串替换前，先 `ruff format` 过一遍，否则锚点失配（本轮 fixture 补丁因此静默失败过一次，改用 Edit 工具才对上）。
