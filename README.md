# Enterprise Multi-Source AI Agent

Internal knowledge and business-data question answering. Canonical behavior remains in
`docs/contracts/` (local development material, not committed).

Implemented: infrastructure, the main LangGraph (Knowledge, Structured Data, General, and
safe routing paths), capability-aware LLM adapters, the layered SQL security boundary, the
RAG ingestion/retrieval chain, Checkpoint-backed HITL export approval, authentication, the
Conversation/Run/Document/Ingestion/Structured Data APIs, SSE streaming, and the Vue3 UI.

## Windows startup

Requires Docker Desktop (Linux containers), Python 3.12, uv, and Node >=22.12.
MySQL and Milvus run in Docker; no host database is required.

```powershell
./scripts/init-env.ps1
uv sync --frozen
docker compose config --quiet
docker compose up -d --build
docker compose ps
Invoke-RestMethod http://127.0.0.1:8000/api/v1/health
$env:SMOKE_BASE_URL = 'http://127.0.0.1:5173'
uv run pytest
uv run pytest tests/unit
uv run pytest tests/integration
uv run pytest tests/e2e -m smoke
uv run ruff check .
uv run ruff format --check .
```

Open http://127.0.0.1:5173 and sign in with `AUTH_BOOTSTRAP_USERNAME` and
`AUTH_BOOTSTRAP_PASSWORD` from `.env` (generated by `scripts/init-env.ps1`).
`GET /api/v1/health/live` checks the application process; `GET /api/v1/health` returns 503
when a dependency is unavailable.

Initialize Demo structured data once the containers are healthy:

```powershell
docker compose exec backend python -m scripts.seed_demo
```

## Local development

Host processes do not resolve Compose DNS, so use the helper that points the application at
the published Compose ports and the offline development providers:

```powershell
. ./scripts/dev-env.ps1
uv run python -m scripts.seed_demo
uv run python -m scripts.verify_live     # end-to-end acceptance evidence
uv run uvicorn backend.api.main:app --host 127.0.0.1 --port 8001 --no-access-log
```

```powershell
cd frontend
npm ci
$env:BACKEND_URL = 'http://127.0.0.1:8001'
npm run dev -- --port 5174
npm run build
```

`scripts/dev-env.ps1` selects `EMBEDDING_PROVIDER=deterministic` and
`LLM_PROVIDER=extractive`, which are offline development profiles: the deterministic
embedding provider produces reproducible vectors, and the extractive reader can only quote
sentences from the authorized retrieval context, so it cannot introduce pretrained
enterprise facts. Use the remote profiles for realistic answers:

```powershell
$env:LLM_PROVIDER = 'remote'; $env:LLM_API_KEY = '<provider key>'
$env:EMBEDDING_PROVIDER = 'siliconflow'; $env:EMBEDDING_API_KEY = '<provider key>'
```

Dependency health is expected to be degraded outside Docker unless the dev environment is
loaded. Use the Compose runtime for full dependency acceptance.

## Runtime modes and configuration

`.env.example` contains no credentials. `scripts/init-env.ps1` generates random private
local credentials once and preserves an existing `.env`. Never commit or print `.env`,
resolved Compose environment, or raw dependency diagnostics. Credentials initialize
MySQL/MinIO on first startup; changing `.env` does not rotate existing volume credentials.

- Container connections use `mysql`, `milvus`, `etcd`, `minio`, and `backend` service names.
- The application account manages business data; the `MYSQL_READONLY_*` account is used only
  by the validated `database_query` path. `create_app` bootstraps that account from
  `MYSQL_ROOT_PASSWORD` at startup when it is configured.
- Backend/frontend ports bind only to host loopback. MySQL and Milvus are published on
  `127.0.0.1:13306` and `127.0.0.1:19530` for host development; storage services stay
  unpublished otherwise.
- Persistent named volumes hold MySQL, Milvus, etcd, MinIO, and SQLite Checkpoints.

```powershell
docker compose logs --tail 50 backend
docker compose stop
docker compose up -d
```

Keep volumes when stopping. Do not use `down -v` unless intentionally deleting local data.

The default LLM profile is remote OpenAI-compatible and does not connect during startup.
Set `LLM_API_KEY` to enable requests. Local execution is opt-in with `LLM_PROVIDER=local`,
`LOCAL_LLM_BASE_URL`, and independent `LOCAL_LLM_*` capability flags. A Local profile that
does not declare `tool_calling` is rejected at the Structured Data Graph boundary. The
Structured Data Agent model is selected by `SQL_AGENT_PROVIDER` (`auto`, `llm`, `scripted`).

## API surface

`/api/v1` provides authentication, Conversation/Message reads, Run creation and status,
`/api/v1/runs/{run_id}/events` SSE streaming with `Last-Event-ID` replay, approval
approve/reject, Document upload/list/delete/reindex, Ingestion Job status/retry, and
read-only Structured Data schema/table/preview reads. There is no arbitrary SQL, Tool,
filesystem, URL, Graph State, or Checkpoint endpoint.

## Known limitations

- MinerU is not deployed here; the lightweight Parser handles text, Markdown, CSV, and JSON.
- MVP mixed Knowledge/Structured Data requests are reported as unsupported.
- Token-level streaming is emitted only when the configured LLM profile supports it; the
  authoritative complete answer always arrives as the terminal `final` event.
- Persistent Checkpoint is limited to the approved Memory/SQLite modes.
